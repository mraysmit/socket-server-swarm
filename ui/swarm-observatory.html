    Design guidelines

    Show what is true, then what is believed

    A node's outline is its real state. The badge on every other node is only the selected server's opinion. Disagreement between the two is the thing to look at.

    State never relies on color

    Each state has a color, a stroke pattern and a word: solid, dashed, dotted. It stays readable in grayscale and for color-blind viewers.

    Motion is traffic, not decoration

    Dots appear only when a real exchange happens, and failed ones turn red and stop short. Pause and speed controls are always within reach.

    One vocabulary with the plugin

    ALIVE, SUSPECT, DEAD, LEFT, bootId, heartbeat and departure states use the plugin's own names, so what you read here matches what the logs and console say.

    Overview, then one server

    Swarm convergence first, then a single server's full member table. Never mix several viewpoints in one table.

    Label simulated values honestly

    Timings and percentages are measured from the run on screen. No claimed guarantees, and demo thresholds are stated.
